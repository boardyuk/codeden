section: security
---

- **Commands run in a folder outside the worktree now ask at Auto and Full, for every provider.** `cd /other && git reset --hard`, `git -C /other clean -fdx`, `make -C /other clean`, `npm --prefix /other install` and the like ran without asking, because they name no path to judge. CodeDen now follows the folder each command runs in, through `cd`, `pushd`, `Set-Location` and `Push-Location` (also in subshells, `bash -c` and `pwsh -Command`), and through a program's own folder option (`git -C`, `make -C`, `npm --prefix`, `pnpm -C`, `yarn --cwd`, `bun --cwd`, `env -C`, `tar -C`, `GIT_DIR=…`). Anything but a read there asks as a write outside the worktree, so Full asks too, and in CodeDen's own home it asks at every level. A `cd` to a folder only known when the command runs (`cd $DIR`, `cd "$(…)"`, `cd -`, `cd ~user`, a wildcard, zsh's `cd old new`) counts as outside until a `cd` to a known folder, and so does a drive switch (`D:`) or a folder option left for `xargs` to fill; `cd "$(git rev-parse --show-toplevel)"` goes to the repository's top folder, and `find … -execdir` runs in the folders it searches. `touch` and `mkdir` (`md`, `New-Item -ItemType Directory`) outside the worktree now ask like other writes. Reads such as `cd ../other && git log` or `git -C ../other status` still run freely, and so does everything in the worktree, temp folders and extra roots. A force push in another repository (`git -C ../other push -f`) now asks as a write outside the worktree, so Full asks for it too.
